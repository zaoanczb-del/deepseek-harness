从 Session 历史到聊天窗体

完成本课后，你能从用户切换 Session 开始，一路追踪到 UserMessageNodeView 或 AssistantNodeView 的 React 渲染。

打开HostClient组装渲染速查表

一、选择 Session 就是打开信号

Client Session service 观察列表中的 current。当前 Session 变化后，followCurrent() 取得稳定的 SessionBinding 并调用 session.open()。open 创建一个按 Session address 绑定的 SessionEventStream。

二、Host 取得一个一致历史 cut

SessionHistoryController.follow() 先安装实时监听器，再调用 ctx.sessionQuery.observeSession()。查询优先使用 live Session；若 Session 是冷的，则从 persistence 恢复一个未挂入 store 的 prepared Session。两条路径都返回固定 cursor、连续 events、header 和 projections。

Opening snapshot 包含尾部事件页、hasMore、cursor、投影 baseline，以及可选的在途 Assistant baseline。监听器先装、snapshot 后读，因此读 snapshot 期间新到的事件会进入 buffer，不会落在缝里。

三、Client 把网络流变成连续窗口

SessionEventStream 继承 Gateway 的 RemoteJournalStream，校验每条 wire event 的 V3 envelope 与连续 seq。opening 变成 replace，旧页变成 prepend，新事件变成 append。断线后按 cursor 追赶；出现缺口时用 tail page 修复。

Session 对象把这些变化写入 MutableSessionEventSource。这个 source 用 concat tree 保存窗口，使尾部 append 和头部 prepend 不必每次复制整份历史；订阅读取 snapshot 时才物化数组。

四、原始事件还不是聊天节点

BoundConversation 订阅事件窗口，再交给 ConversationNodeAssembler。Assembler 通过可注册 Definition 识别事件：

  • user/message 形成 user、steering 或 context 节点。
  • step/start 建立 Assistant step context。
  • assistant/live-chunk 增量更新该 step。
  • assistant/message 结算为持久 Assistant 节点。
  • tool/call 与 tool/result 合成工具节点。

Chat snapshot builder 最终生成 { order, nodes, timeline, navigation }。高频 token chunk 按 animation frame 合并发布；持久节点和结构变化立即发布。

五、React 只消费 ChatSnapshot

ChatView 用 useChat() 订阅 ChatSnapshot，遍历 order。每个 key 进入 ChatNodeSeat；Seat 根据 node.kind 交给 keyed slot，例如 user → UserMessageNodeView，assistant-step → AssistantNodeView。因此 UI 组件无需认识 Session persistence、RPC 或事件缺口。

快速检索练习

用户点击“加载更早”后，新的历史应该怎样进入现有窗口？

建议追踪的一个事件

SessionEvent<'user/message'>
→ SessionEventEntry
→ SessionEventLikeEntry
→ MutableSessionEventSource.append/replace
→ messageDefinition.match/start
→ ChatSnapshot.nodes
→ ChatNodeSeat
→ UserMessageNodeView
