# Agent Note: 精简且按年级分层的 Story Skill

Status: implemented

[English](2026-08-26-concise-grade-aware-story-skill.md) | 中文

## Problem

按课次创作的 Story 流程原先由六份年级提示词和一份共享旧规则组成。它们重复风格要求，加入僵硬的段落和数量清单，还保留了当前课次创作入口不使用的工具与 JSON 指令。重复内容使模型可见规则过长，也让「生字覆盖率」和「表达自然」等要求发生冲突。

## Decision

通用课次 Story 流程只使用一份 `skills/story/SKILL.md` 作为模型可见来源，保留用户选择的年级、主题、素材、本课字词、年龄适配、因果叙事和 Markdown 输出要求。用户提供的目标字词须自然覆盖 65% 以上，并在第一次目标出现处用 Markdown 粗体标出，供渲染突出显示；模型不能把它们列在文末或用作人名。年级差异压缩为三档复杂度，只保留正文总字数范围，其中 P3 固定为 350–450 个汉字。工具编排、JSON 序列化、句数、段数、风格清单、标题示例和词语速查表不属于该 skill。刊物格式的结构存在实质差异且互斥，因此按[创作目录决策](../feature/2026-08-24-authoring-mode-plugin.zh.md)使用独立 skill。

## Alternatives considered

**保留 P1–P6 六份附属提示词。** 未采用，因为这些文件重复表达相同的行为，还要求当前 Skill 流水线额外选择并注入一份提示词，而现有流程不会这样做。

**保留精确的段落、句子、对话和风格数量。** 未采用，因为这些数量限制不能稳定表达用户真正需要的故事质量；因果结构和年级适配已经足够指导模型。

**保留旧的生字工具和 JSON 响应协议。** 未采用，因为课文生字、生词已经作为用户消息对模型可见，引用的工具在当前包中没有实现，且通用 Story skill 返回 Markdown。

## Consequences

通用 Story skill 更短，并只有一个来源。模型可以自行决定段落、句式节奏、对话数量和修辞，同时仍须遵守目标字词使用与突出显示、正文总字数和年级复杂度。若消费方需要结构化输出，应在创作指导之外单独定义该协议。

## Testing

`story` 目录只包含一份 `SKILL.md`，不包含按年级拆分的附属提示词。skill 明确记录 P3 为 350–450 个汉字，要求目标字词覆盖率超过 65%，并在第一次出现时用 Markdown 突出显示，也不要求只能输出 JSON。草稿与组件测试覆盖独立的选择和调用路径；Web 快照仍只覆盖 UI。
